# 架构、加速边界与一致性

[English](architecture.md) · [使用方法](README.zh-CN.md) · [调度优化实测](https://github.com/hanruihua/ir-sim/pull/386)

## 现有仿真契约

`irsim.make()` 构建 `EnvBase`、YAML 配置、`World`、对象工厂、运动学/几何 handler、行为注册表、传感器及可选 Matplotlib 渲染。对象中的状态数组可变，setter 负责更新依赖的几何与缓存。`env.get_msg()` 会复制状态和传感器数组，但“有副本”不等于任意并发调用时都能与写入者原子同步。

普通 step 分发动作/组行为，按既有对象顺序推进单体，重建几何索引，在 contact 模式求解接触，更新传感器、推进时钟并检查状态。单体行为可能读取到本 step 中已经移动过的邻居，接触求解也依赖有序 sweep。直接换成同步数组更新，会改变语义，即使计算公式看似相同。

## 两项改造的边界

| 层次 | 改动 | 状态所有权与行为 |
| --- | --- | --- |
| 调度优化 | 内置 dash 声明无需邻居；动作身份映射按每次调用建立 | 现有对象仍是权威状态，不改变物理/传感器顺序 |
| 可选 MCP 适配器 | 独立仿真进程、复制读模型、带版本的有界命令网关 | 旧状态留在所属进程，读者拿不到可变数组引用 |

相关的[调度 PR #386](https://github.com/hanruihua/ir-sim/pull/386)与本集成独立。实测 dash-1000 **2.736×**、ID-action-1000 **2.688×** 属于调度优化，不是 ECS、MCP、渲染或模型推理的加速。1/10 对象场景基本不变。30 组对应基准的逐步轨迹和最终 WorldState 摘要一致。原始样本、TDD 失败证据、运行环境与限制见独立性能报告。

## MCP 的进程与状态边界

本地 Gemma 与 Host 交互；Host 经官方 MCP SDK，通过 stdio JSON-RPC 访问服务；服务将有界命令串行发给 spawn 创建的仿真进程；仿真每完成 tick，发布副本到有界队列；服务更新读模型供后续读取。英文版包含对应结构图。

`irsim_mcp` 的协议进程不导入仿真器。子进程先将诊断输出重定向到 stderr，再导入 IR-SIM，避免污染 JSON-RPC stdout。主线程独占世界与 GUI，隔离全局参数代理，也避开 Matplotlib 跨线程问题。Gemma 思考期间继续处理 GUI 事件，但没有命令就不推进仿真时间；这是命令驱动的仿真，不是独立自由运行的实时设备。

每个完整 tick 后，写侧发布拥有数据副本的 JSON 观测。队列最多保留两个快照，读侧慢时丢弃旧遥测。读取会排空可用遥测并返回深拷贝；`publication_sequence` 保证延迟到达的快照不会覆盖更新的命令回执。读者可能跳帧，也可能看到正在执行的命令；`command_in_progress`、帧号、采集时间和 `age_seconds` 明确表示这一点。不会读到运动学/传感器/状态更新到一半的帧。本次没有引入数据库、事件存储或第二套可写 ECS 权威状态。

## 命令一致性契约

- 阻塞 IPC 锁串行执行写命令；即使异步工具 handler 被取消，仍在运行的线程持锁，不会交错读写同一个连接。
- `expected_version` 绑定所观测的 session、epoch 和 revision。每次 tick/修改推进 revision；基于运动中旧观测排队的命令，会在前一命令完成后被拒绝。
- 修改前完成验证。未知机器人/路点、布尔值或非法步数、非有限坐标、越界目标和受阻导航，都不会部分改变状态。
- 修改目标后不推进时钟，但刷新衍生状态与传感器。reset 增加 epoch，防止上一轮 frame=0 的旧观测被接受。
- 256 条命令回执避免重复运动。同 ID 配不同命令/参数/版本会失败；相同请求的重试返回旧动作结果和**当前**状态，不能把旧帧重新发布。
- 取消在 tick 边界生效，报告真实完成步数；碰撞提前结束命令；到达由仿真状态判定，不相信模型自行宣称成功。
- 仿真异常或 IPC 超时使会话失效。部分命令可能已经执行，结果未知时必须重建/重新观测，不能自动重放。

当前读模型覆盖平面示例和 lidar 有效掩码，不修改核心 `WorldState` API。MCP 的只读/控制开关约束适配器，不会限制另一个应用自己持有的直接环境引用。启动时只接受受信任的本地 YAML；工具不提供任意 Python、文件系统或 shell 执行。Demo Host 仅接受 HTTP loopback 模型地址。

## 哪些部分适合继续迁移

| 候选部分 | 机会 | 迁移条件 |
| --- | --- | --- |
| 复制的状态/观测数组 | 批量导出、分析、渲染准备 | 单写者、明确完整 tick 边界、独占输出缓冲 |
| 同质纯运动学 | 为部分 omni/diff/dash 群体做 NumPy 批量计算 | 显式选择；保持公式、限幅、角度、停止/到达标志、随机数消耗；逐帧比较 |
| 候选生成/几何变换 | 批量坐标变换或 broad phase 数组 | 保持 Shapely 精度、几何有效性和 narrow phase 语义，实测真实场景 |
| 依赖邻居的单体行为 | 有批处理潜力 | 保留逐对象实时邻居可见性，或显式提供另一个版本的同步模式 |
| Contact、自定义插件、混合/含噪模型 | 语义风险较高 | 先保留旧路径，差分测试覆盖顺序、副作用、随机数与缓存失效后再考虑 |

可以分阶段迁移，但现有证据不足以证明一次性更换权威存储和物理调度安全。后续数组路径应先筛选兼容实体，在独立输出缓冲计算，经既有状态更新边界提交，不兼容组件回退旧路径。避免双写两套权威状态，也避免删除/reset 后仍被外部持有的数组 view。

存读分离主要改善隔离、可观测性与调度弹性，复制和序列化本身也有成本，不能据此声称物理运算变快。任何 ECS 批量路径默认启用之前，都应测试包含传感器/碰撞/渲染选项的完整 step，规定差分容差，并同时检查小场景回退和大场景收益。已有 30 组相等证据只保护调度优化。

## 验证范围

测试使用真实 spawn 仿真进程及官方 SDK stdio 会话，覆盖版本拒绝、幂等重试、reset、输入边界、碰撞、受阻导航、并发完整帧读取、取消和进程死亡。真实 Gemma 测试显式启用并单独执行。录像任务证明本机这条模型/场景/控制器链路，不能推广为通用自主导航可靠性。视频记录真实窗口，结构化回执负责物理结果断言。[验证记录](validation.json)保留结果与哈希。
