# MCP 运行架构与一致性

[English](architecture.md) · [使用方法](README.zh-CN.md) · [调度优化实测](https://github.com/hanruihua/ir-sim/pull/386)

## 现有仿真契约

`irsim.make()` 构建 `EnvBase`、YAML 配置、`World`、对象工厂、运动学/几何 handler、行为注册表、传感器及可选 Matplotlib 渲染。对象中的状态数组可变，setter 负责更新依赖的几何与缓存。`env.get_msg()` 复制状态和传感器数组。MCP 写侧在完整 tick 边界采集这些数据，使观测与写入同步。

普通 step 分发动作/组行为，按既有对象顺序推进单体，重建几何索引，在 contact 模式求解接触，更新传感器、推进时钟并检查状态。单体行为可能读取到本 step 中已经移动过的邻居，接触求解也依赖有序 sweep。

## MCP 的进程与状态边界

本地 Gemma 与 Host 交互；Host 经官方 MCP SDK，通过 stdio JSON-RPC 访问服务；服务将有界命令串行发给 spawn 创建的仿真进程；仿真每完成 tick，发布副本到有界队列；服务更新读模型供后续读取。英文版包含对应结构图。

`irsim_mcp` 的协议进程不导入仿真器。子进程先将诊断输出重定向到 stderr，再导入 IR-SIM，避免污染 JSON-RPC stdout。主线程独占世界与 GUI，隔离全局参数代理，也避开 Matplotlib 跨线程问题。仿真时间由 MCP 命令推进，Gemma 思考期间继续处理 GUI 事件。

每个完整 tick 后，写侧发布拥有数据副本的 JSON 观测。队列最多保留两个快照，读侧慢时丢弃旧遥测。读取会排空可用遥测并返回深拷贝；`publication_sequence` 保证延迟到达的快照不会覆盖更新的命令回执。读者可能跳帧，也可能看到正在执行的命令；`command_in_progress`、帧号、采集时间和 `age_seconds` 明确表示这一点。不会读到运动学/传感器/状态更新到一半的帧。现有仿真对象仍持有唯一的权威状态。

## 命令一致性契约

- 阻塞 IPC 锁串行执行写命令；即使异步工具 handler 被取消，仍在运行的线程持锁，不会交错读写同一个连接。
- `expected_version` 绑定所观测的 session、epoch 和 revision。每次 tick/修改推进 revision；基于运动中旧观测排队的命令，会在前一命令完成后被拒绝。
- 修改前完成验证。未知机器人/路点、布尔值或非法步数、非有限坐标、越界目标和受阻导航，都不会部分改变状态。
- 修改目标后不推进时钟，但刷新衍生状态与传感器。reset 增加 epoch，防止上一轮 frame=0 的旧观测被接受。
- 256 条命令回执避免重复运动。同 ID 配不同命令/参数/版本会失败；相同请求的重试返回旧动作结果和**当前**状态，不能把旧帧重新发布。
- 取消在 tick 边界生效，报告真实完成步数；碰撞提前结束命令；到达状态读取仿真器的到达标志。
- 仿真异常或 IPC 超时使会话失效。部分命令可能已经执行，结果未知时必须重建/重新观测，不能自动重放。

当前读模型覆盖平面示例和 lidar 有效掩码，不修改核心 `WorldState` API。MCP 的只读/控制开关约束适配器，不会限制另一个应用自己持有的直接环境引用。启动时只接受受信任的本地 YAML；工具不提供任意 Python、文件系统或 shell 执行。Demo Host 仅接受 HTTP loopback 模型地址。

## 验证范围

测试使用真实 spawn 仿真进程及官方 SDK stdio 会话，覆盖版本拒绝、幂等重试、reset、输入边界、碰撞、受阻导航、并发完整帧读取、取消和进程死亡。真实 Gemma 测试显式启用并单独执行。录像任务使用单个平面 omni 机器人、dash 控制、lidar2d 和静态障碍。视频记录真实窗口，结构化回执负责物理结果断言。[验证记录](validation.json)保留结果与哈希。
